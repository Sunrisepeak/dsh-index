被检查挡下来的

这一天真正起作用的不是写了多少代码，是几道拒绝放行的门。左列是当时以为的，右列是测出来的。

以为实测
--ignore-scripts 安全 —— 根 package.json 没有 scripts 该 flag 作用于整棵树。node-pty 在 Linux 无预编译产物，跳过安装脚本后 --version 照过，但每次 profile 启动都死
描述符里的版本号和 pin 的 commit 是一致的 来自相隔几分钟的两次快照。169 个里 19 个对不上，另有 1 个在 pin 处已不再是 bundle
theme.style: "dark" 能强制深色 生成 var fixed = &#34;dark&#34;; —— script 里实体不解码，整段 IIFE 语法错误，语言重定向一并失效
profile 会跟随当前 subos XLINGS_SUBOS 这个变量不存在，分支是死代码，所有插件都落进 web。正解是 system.subos_sysrootdir() 这个 API
卡片上印 dsh plugin add <包名> 方便复制 这条命令会 404 —— 包名在本生态不是可解析标识符，正是我自己在文档里反复强调的那点
声明 xim:node 和 xim:npm 更保险 node 本来就提供 npm，多这一条造成同一 xvm 名双 owner —— 规范里点名最危险的那种
169 个 bundle 都能装 至少 45 个谁都装不上：依赖不存在、依赖范围无解、main 不在自己的 tarball 里
批量报告记下了失败原因 记的是 Python traceback。修了两遍才拿到 pnpm 自己的报错 —— 同一个盲点低一层又出现一次

贯穿的一条：凡是「验证过」的结论，都要问清楚验的是哪个面。 dsh --version 通过不代表 dsh 能用；描述符生成成功不代表版本号描述的是那次提交的字节； 测试通过不代表它真的跑了 —— 有一条 sha 校验用例在 source 字段删除后每次提前返回，静默失效。

架构上的两个决定

  • 许可证决定分发方式，不是偏好。镜像等于再分发，所以只有许可证允许的才进镜像 （双镜像 + sha256 + 免构建授权）；其余直连上游，站点如实标注「无 CN 加速、上游删库就装不回来」。 无法识别许可证的按 GitHub 的惯例标 unknown，不删除 —— 它们装得上，只是不能镜像。
  • 范式统一到可以模板化。169 个 bundle 里 166 个连 patch 路径都相同， 所以描述符只写数据，四个生命周期 hook 全部来自一份 template.lua， 由索引构建期追加 —— 上游改了用法，改一个文件而不是 169 个。
